# Stage 1 verification and handoff

Stage 1 implements standard/multiple-choice polling, per-topic capacity signups, atomic changes/cancellation, configurable organizer voting, result visibility, anonymous identity protection, lifecycle management, and owner/admin management with participant search/filter/sort/pagination. Stages 2–4 remain pending.

## Validation

- `npm run check`: lint, TypeScript checks, 48 automated tests, frontend/backend build, and offline infrastructure checks pass.
- `npm run format:check`: passes.
- `npm run test:e2e`: installed-browser tests pass, including standard poll creation/voting, signup creation through the availability/capacity form, owner voting restriction, full-topic display, admin search/removal, selection switching, cancellation and closing. Existing event/waitlist, appointment, attendee CSV, account and logout flows pass with no browser runtime errors.
- Migration tests verify legacy counts and organizer votes, a full 2,000-vote poll, repeatable reopen, unknown historical timestamps, and complete rollback on malformed legacy data. New and legacy anonymous activity is redacted.
- Independent SQLite connection tests verify last-place races, duplicate requests and atomic switching. Existing event concurrency regressions pass.
- Two DynamoDB Local integration tests are skipped in ordinary tests. Poll transaction integration coverage was added, but Docker/DynamoDB Local execution is unavailable on this workstation; DynamoDB execution is not claimed verified.

Tests use memory/temporary databases. The live `data/hub.sqlite` has not been opened or migrated. Browser screenshots generated by the existing regression script were reviewed as test output and existing repository screenshots restored to avoid unrelated artifact changes.

## Files and operations

The main changes are in `backend/src/polls.ts`, `backend/src/service.ts`, `backend/src/app.ts`, `backend/src/store.ts`, `shared/types.ts`, `frontend/Polls.tsx`, `frontend/ManagementTable.tsx`, and `frontend/App.tsx`. `backend/src/errors.ts` shares the existing HTTP error class without introducing storage/service import cycles. Trusted `scripts/create-user.ts` now accepts `admin`. Tests and browser smoke coverage are expanded; README/API/database/security documentation is updated.

No dependencies were installed. SQLite migration `001-polls` runs automatically on the next database open; a migrations ledger prevents repeat execution. `scripts/migrate-polls.ts` provides resumable conditional upgrades for configured local DynamoDB and records completion. Back up an existing database before starting the updated application; README documents safe backup/recovery and administrator provisioning.

Run locally with the existing `npm run dev`, or `npm run build` then `npm start` using the documented local `APP_ORIGIN`. No external credentials are required. To exercise the feature, create a signup with a one-place topic, register in separate student sessions, verify full/switch/cancel behavior, and inspect participants as owner/admin. Anonymous polls permit aggregate management only.

Prototype limits remain explicit: 2–8 options, 2,000 active participants, 4,000 stored historical selections, and a 290 KB mutation bound. Poll CSV/XLSX exports and spreadsheet importing remain Stage 4. Administrator scope is application-wide for polls in the existing single-workspace application. Office-hours redesign has not started; Stage 2 awaits approval.

## Polling UI follow-up

`frontend/PollForm.tsx` now provides individual option fields, adjacent capacities, add/remove controls, field-level validation, retained values across type changes, grouped checkbox settings, and a Cancel/Create footer. Poll cards have spaced controls, clickable labels, wrapped names, selected/full states, concise capacity statistics and saved-registration confirmation. Poll-specific modal styles provide a wider desktop layout and a scrolling mobile form with a visible footer. Backend voting, capacity, authorization, API formats and database records were not changed by this follow-up; no dependencies or migrations were added.

`npm run check` passes with 55 tests; `npm run format:check` and `npm run test:e2e` pass. Browser checks include dynamic signup creation, add/remove and retained capacities, mobile modal scrolling, no horizontal overflow, long option names, voting, changes/cancellation and administrator management. Desktop/mobile screenshots were visually inspected under `artifacts/poll-ui/`; unrelated repository screenshots were restored. The two DynamoDB Local tests remain skipped because that environment is unavailable.
